# Smoke-checklist (Шаг 6.4)

Цель: быстро проверить, что ключевые пользовательские сценарии работают end-to-end после изменений.

## Предусловия

1. Поднят backend на `http://localhost:3000`.
2. Поднят frontend на `http://localhost:5173`.
3. В БД есть тестовые данные (или доступны формы создания).

## Сценарий 1 — Логин

1. Открыть страницу `/login`.
2. Ввести валидные `email`, `password`, `role`.
3. Нажать «Войти».
4. Проверить:
   - происходит переход на защищённый маршрут;
   - в `localStorage` записан `diploma-auth`;
   - после обновления страницы сессия сохраняется.

## Сценарий 2 — Создание абонента

1. Перейти на страницу «Абоненты».
2. Заполнить форму создания абонента валидными данными.
3. Отправить форму.
4. Проверить:
   - отображается уведомление об успешном создании;
   - новая запись появляется в списке;
   - фильтр/поиск находит созданного абонента.

## Сценарий 3 — Создание заявки

1. Перейти на страницу «Заявки».
2. Заполнить форму создания заявки.
3. Отправить форму.
4. Проверить:
   - отображается уведомление об успешном создании;
   - новая заявка появляется в списке;
   - статус заявки соответствует ожидаемому (`NEW` по умолчанию, если применимо).

## Сценарий 4 — Проверка сообщений об ошибках

1. На форме заявки/абонента отправить заведомо некорректные данные.
2. Проверить, что показывается человекочитаемое сообщение (не «Request failed»).
3. При проблемах сети/таймауте убедиться, что показываются специальные fallback-сообщения.

## Быстрый автоматизированный smoke (backend)

Можно запустить базовую автоматизированную проверку backend-компонента:

```bash
BASE_URL=http://localhost:3000/api/v1 ./scripts/smoke-backend.sh
```

Скрипт проверяет:

- `GET /health` (ожидается `status: ok`);
- `POST /auth/login` (ожидаются `accessToken` и `refreshToken`).

## Быстрый автоматизированный smoke (frontend)

Можно запустить базовую автоматизированную проверку frontend:

```bash
FRONTEND_URL=http://localhost:5173 ./scripts/smoke-frontend.sh
```

Скрипт проверяет:

- доступность index-страницы;
- доступность маршрута `/login`;
- наличие ожидаемых маркеров страницы логина.

## Запуск всего smoke-набора одной командой

```bash
./scripts/smoke-all.sh
```

Или через Makefile:

```bash
make smoke
```

Скрипт последовательно запускает:

1. `scripts/smoke-backend.sh`
2. `scripts/smoke-frontend.sh`

Если любой из шагов падает — `smoke-all` завершается с ошибкой.

## Критерии прохождения smoke

- Все 4 сценария проходят без ручных исправлений в коде.
- Нет критических JS-ошибок в консоли при выполнении шагов.
- После smoke не нарушены существующие пользовательские потоки (логин, просмотр списков, создание сущностей).
