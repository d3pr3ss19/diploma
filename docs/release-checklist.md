# Release checklist (Шаг 8)

> Чек-лист предзащиты и финальной упаковки дипломного проекта.

## 1) Готовность к релизу

- [ ] Все шаги roadmap в `docs/progress.md` закрыты или явно перенесены в backlog.
- [ ] Все обязательные артефакты диплома синхронизированы с актуальным кодом.
- [ ] Проект собирается локально по инструкции из `README.md`.
- [ ] Определён финальный commit/tag для демонстрации.

## 2) Backend readiness

- [ ] Установлены зависимости и выполнены Prisma-команды (`generate`, `migrate deploy`).
- [ ] Выполнен seed демо-пользователей (`seed:auth-users`).
- [ ] Health endpoint отвечает стабильно.
- [ ] Базовые auth-сценарии проходят: login, refresh, logout.
- [ ] Проверено, что RBAC-сценарии не регресснули.

Рекомендуемые команды:

```bash
cd backend && npm run prisma:generate
cd backend && npm run start:dev
```

## 3) Frontend readiness

- [ ] Frontend стартует локально без ошибок.
- [ ] Login-форма работает с backend и корректно показывает ошибки.
- [ ] Protected routes и logout ведут себя ожидаемо.
- [ ] Страницы Абоненты / Заявки / Лицевой счёт открываются и загружают данные.
- [ ] Проверен сценарий авто-refresh на 401.

Рекомендуемые команды:

```bash
cd frontend && npm run dev
make test-frontend
```

## 4) Tooling & quality gates

- [ ] Локальный запуск backend/frontend стабилен.
- [ ] Проверены ключевые сценарии вручную (login/roles/billing/requests).
- [ ] Ошибки в UI/API обрабатываются контролируемо.

## 5) Demo package

- [ ] Подготовлен краткий demo-скрипт для защиты (`docs/demo-defense-scenario.md`).
- [ ] Подготовлены учётные данные демо-пользователей (без секретов прод-среды).
- [ ] Подготовлен план fallback при сбое сети/среды (локальный запуск).
- [ ] Зафиксированы 2–3 ключевых value-point'а системы для комиссии.

## 6) Документация

- [ ] `README.md` отражает актуальный процесс запуска.
- [ ] `docs/progress.md` содержит текущий этап и следующий шаг.
- [ ] `docs/project-completion-checklist.md` актуализирован при необходимости.
- [ ] Список команд в README проверен на исполнимость.

## 7) Финальный dry-run перед защитой

- [ ] Выполнен полный прогон минимум один раз без ручного редактирования кода.
- [ ] Проверено время запуска backend+frontend и стабильность auth-flow.
- [ ] Проверена демонстрация ролей (admin/operator/subscriber).
- [ ] Проверены ключевые CRUD-сценарии и обработка ошибок.
- [ ] Подготовлен короткий «план Б» (скриншоты/логика рассказа) на случай сбоя.

## 8) Definition of Done для Шага 8

Шаг 8 считается закрытым, когда:

1. Готовы релизный чек-лист и демо-сценарий.
2. Подтверждён повторяемый локальный запуск проекта.
3. Пройдены ключевые ручные сценарии демонстрации.
4. Документация синхронизирована с кодовой базой.
