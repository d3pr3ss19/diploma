# Demo defense scenario (Шаг 8)

> Компактный сценарий демонстрации проекта на защите (10–15 минут).

## 0) Цель показа

Показать, что система:

1. Реально запускается локально.
2. Имеет рабочую роль-ориентированную авторизацию.
3. Поддерживает базовые бизнес-сценарии (абоненты/заявки/лицевой счёт).
4. Имеет покрытие smoke/e2e/tooling-проверками.

## 1) Подготовка окружения (до начала выступления)

1. Запустить backend и frontend по `README.md`.
2. Подготовить демо-пользователей (`admin`, `operator`, `subscriber`) в БД.
3. Проверить, что открывается `/login` и backend health endpoint.
4. Держать открытой вкладку с терминалом для быстрых проверок.

## 2) Структура показа по времени

### Блок A (2–3 мин): контекст и архитектура

- Кратко показать стек: React + Vite + TS, NestJS + Prisma + PostgreSQL.
- Пояснить, что auth построен на access/refresh токенах.
- Указать, где находится roadmap и прогресс (`docs/progress.md`).

### Блок B (4–6 мин): live user-flow

1. Вход под `operator`.
2. Переход на страницу «Абоненты»: показать загрузку списка и фильтры.
3. Переход на страницу «Заявки»: показать список и создание заявки.
4. Переход в «Лицевой счёт»: показать сводную информацию.
5. Выход (`logout`) и повторный вход под другой ролью (например, `admin`).

### Блок C (2–3 мин): безопасность и устойчивость

- Кратко показать, что защищённые route недоступны без токена.
- Пояснить auto-refresh access token при 401.
- Упомянуть, что refresh-сессии persist в БД и проверяются скриптами.

### Блок D (1–2 мин): качество и автоматизация

Показать (или озвучить последний успешный прогон) команды:

```bash
make smoke
make e2e-auth-integration
make verify-tooling
```

## 3) Минимальный «боевой» сценарий для защиты

Если времени мало, выполняем только:

1. Login под `operator`.
2. Просмотр списка абонентов.
3. Создание одной заявки.
4. Logout и короткий комментарий про refresh/RBAC.

## 4) План Б при техническом сбое

- Если frontend не стартует: показать backend API + ранее подготовленные скриншоты.
- Если backend не доступен: показать структуру модулей и скрипты проверок.
- Если сеть/зависимости не поднялись: перейти к заранее подготовленному walkthrough по документации.

## 5) Что проговорить в выводах

- Проект доведён до состояния воспроизводимого локального запуска.
- Реализована и проверена auth-модель с access/refresh и logout-инвалидацией.
- Подготовлен релизный пакет для предзащиты: чек-лист, demo-сценарий, smoke/e2e/tooling-проверки.
